### Overview

**USDZ Validation Kit** is a Swift library and macOS command-line tool for inspecting packaged 3D assets before delivery. It checks USDZ packaging, supported package-local references, and configurable file and texture budgets, then produces a report that separates observed defects from checks it could not complete.

The project provides the reusable `USDZValidation` library and the `usdz-validator` executable. Native inspection reads one local file without extracting its contents, requiring USD tools, or accessing the network. This makes the same checks available to a developer at the terminal or to a Swift application integrating the library. The [v0.1.0 release](https://github.com/Light2288/usdz-validator/releases/tag/v0.1.0) is an initial working demo, distributed under the MIT license.

### Motivation

A 3D asset's delivery package can have problems that are independent of how its scene looks: inconsistent archive records, unsafe member names, missing internal references, or textures that exceed a delivery budget. These checks benefit from repeatable rules and reports that can be inspected or consumed by automation.

USDZ Validation Kit makes those packaging checks explicit while keeping their limits visible. A finding records an observed problem; coverage describes what was inspected; a separate gate decision determines whether the result meets the selected acceptance policy. That distinction helps callers avoid treating an uninspected dependency as a clean bill of health.

### System Architecture

The project separates inspection from command-line operation:

- **Reusable library:** `USDZValidation` owns configuration, file snapshots, validation, findings, coverage, gate policy, and report encoding. It has no third-party dependencies and does not write to standard output or terminate the caller's process.
- **Thin CLI:** `usdz-validator` uses Swift Argument Parser to expose validation and rule-catalogue commands. It selects a profile, loads explicit budget configuration, and sends the report to standard output or a local file.
- **Bounded native pipeline:** Archive indexing and an in-memory package namespace establish which members can be inspected. Subsequent checks examine stored payloads, supported lexical USDA references, encoded-byte budgets, and supported texture headers under fixed resource limits.
- **Reports and optional checker:** Text, versioned JSON, and SARIF encoders expose the result. An explicitly requested adapter can run a supported installed Apple `usdchecker`, recording its outcome separately from native findings and coverage.

### Key Features

- **Package structure:** Checks supported ZIP metadata, stored-file sizes, 64-byte payload alignment, and CRC-32 checksums. Unsafe indexing prerequisites stop dependent inspection rather than producing speculative findings.
- **Package-local paths:** Rejects unsafe member names and conflicting entries, then resolves supported asset paths inside the package without reading authored references from the host filesystem.
- **Lexical USDA references:** Recognizes supported asset literals while distinguishing comments and strings. Missing package-local targets can be reported without claiming to parse full USD grammar or composition.
- **Delivery budgets:** Configurable thresholds cover archive size, individual file size, file count, individual and total encoded texture bytes, and supported texture dimensions. Encoded-byte totals do not estimate decoded image or GPU memory; dimension checks inspect supported headers without decoding pixels.
- **Reports for automation:** Text, JSON, and SARIF reports preserve stable finding identities and explicit coverage information. Warning thresholds and incomplete-coverage acceptance configure the gate without removing findings or changing what was checked.
- **Versioned profiles:** `general-v1` selects the native checks; `apple-portable-v1` adds a warning-only advisory subset. Neither profile certifies compatibility with an Apple renderer.

### Verification

The project's [recorded v0.1 verification](https://github.com/Light2288/usdz-validator/blob/main/docs/verification/release-summary.md) includes debug, release, and Address Sanitizer test suites, dedicated CLI process checks, schema validation, executable examples, golden report comparisons, adversarial checks, and resource measurements. These records document the validator's verification on its recorded host and corpus.

Original fixtures and fixed expected reports exercise malformed containers, path handling, coverage gaps, and output contracts. Separate real-asset checks document both success and failure from the optional installed checker, while retaining native binary-reference coverage gaps. Resource measurements are evidence for the measured cases, not universal memory or timing guarantees; minimum-target and cross-host verification remain deferred.

### Current Limits

Native reference inspection is lexical and package-local. It does not parse binary-USDC dependencies or perform complete USD composition or conformance validation. A successful optional checker run does not complete native USDC reference coverage. Exit `0` means the configured gate accepted the result; `--allow-incomplete` accepts native coverage gaps without changing that coverage.

The optional `--usdchecker` path is for trusted input and supports the pinned installed Apple USD Tools version 0.25.11. Its parsers and resolvers may access filesystem or network resources beyond the native package boundary; it does not have an external filesystem/network sandbox.

The recorded verified environment is macOS 27.0.1, Xcode 27.1, and Swift 6.4 on arm64. The package declares Swift 6 tools and a macOS 15 deployment target, but macOS 15 / Xcode 16 / Swift 6.0 compatibility remains intended and unverified. Intel and non-macOS execution are outside v0.1 support.

The kit does not repair, convert, render, or preview assets. Passing a gate is not certification of complete USD conformance, Apple renderer compatibility, or asset security.

### Panoramica

**USDZ Validation Kit** è una libreria Swift e uno strumento da riga di comando per macOS per ispezionare asset 3D prima della consegna. Verifica la struttura dei pacchetti USDZ, i riferimenti interni supportati e i limiti configurabili per file e texture, producendo un report che distingue i difetti osservati dalle verifiche che non è stato possibile completare.

Il progetto offre la libreria riutilizzabile `USDZValidation` e l'eseguibile `usdz-validator`. L'ispezione nativa legge un singolo file locale senza estrarne il contenuto, richiedere strumenti USD o accedere alla rete. Le stesse verifiche sono quindi disponibili sia a uno sviluppatore dal terminale sia a un'applicazione Swift che integra la libreria. La [versione v0.1.0](https://github.com/Light2288/usdz-validator/releases/tag/v0.1.0) è una prima demo funzionante, distribuita con licenza MIT.

### Motivazione

Il pacchetto di consegna di un asset 3D può presentare problemi indipendenti dall'aspetto della scena: record dell'archivio incoerenti, nomi delle voci non sicuri, riferimenti interni mancanti o texture che superano i limiti previsti. Per queste verifiche sono utili regole ripetibili e report consultabili o utilizzabili da un'automazione.

USDZ Validation Kit rende esplicite queste verifiche sulla struttura dei pacchetti, mantenendone visibili i limiti. Una segnalazione registra un problema osservato; la copertura descrive ciò che è stato ispezionato; una decisione di accettazione separata stabilisce se il risultato soddisfa la politica selezionata. Questa distinzione aiuta chi integra il kit a non considerare una dipendenza non ispezionata come priva di problemi.

### Architettura del sistema

Il progetto separa l'ispezione dalle operazioni da riga di comando:

- **Libreria riutilizzabile:** `USDZValidation` gestisce configurazione, snapshot del file, validazione, segnalazioni, copertura, politica di accettazione e codifica dei report. Non ha dipendenze di terze parti, non scrive sullo standard output e non termina il processo chiamante.
- **CLI essenziale:** `usdz-validator` usa Swift Argument Parser per esporre i comandi di validazione e del catalogo delle regole. Seleziona un profilo, carica una configurazione esplicita dei limiti e invia il report allo standard output o a un file locale.
- **Pipeline nativa con limiti di risorse:** L'indicizzazione dell'archivio e uno spazio dei nomi del pacchetto mantenuto in memoria stabiliscono quali voci possono essere ispezionate. Le verifiche successive esaminano i contenuti memorizzati, i riferimenti lessicali USDA supportati, i limiti sui byte codificati e le intestazioni delle texture supportate, rispettando limiti fissi di risorse.
- **Report e verificatore opzionale:** I codificatori di testo, JSON con schema versionato e SARIF espongono il risultato. Un adattatore richiesto esplicitamente può eseguire una versione supportata di `usdchecker` di Apple installata sul sistema, registrandone l'esito separatamente dalle segnalazioni e dalla copertura native.

### Funzionalità principali

- **Struttura del pacchetto:** Verifica i metadati ZIP supportati, le dimensioni dei file memorizzati, l'allineamento dei contenuti a 64 byte e i checksum CRC-32. Se mancano i prerequisiti per un'indicizzazione sicura, le ispezioni dipendenti si interrompono senza produrre segnalazioni speculative.
- **Percorsi interni:** Rifiuta nomi delle voci non sicuri e voci in conflitto, quindi risolve i percorsi degli asset supportati all'interno del pacchetto senza leggere i riferimenti dichiarati dal filesystem del sistema ospitante.
- **Riferimenti lessicali USDA:** Riconosce i riferimenti letterali agli asset supportati, distinguendo commenti e stringhe. Può segnalare destinazioni interne mancanti senza pretendere di interpretare l'intera grammatica USD o la composizione.
- **Limiti per la consegna:** Soglie configurabili riguardano dimensione dell'archivio, dimensione del singolo file, numero di file, byte codificati delle singole texture e del loro totale, e dimensioni delle texture supportate. I totali dei byte codificati non stimano la memoria delle immagini decodificate o della GPU; le verifiche dimensionali esaminano le intestazioni supportate senza decodificare i pixel.
- **Report per l'automazione:** I report testuali, JSON e SARIF mantengono identificativi stabili delle segnalazioni e informazioni esplicite sulla copertura. Le soglie di avviso e l'accettazione di una copertura incompleta configurano la decisione finale senza eliminare segnalazioni né modificare ciò che è stato verificato.
- **Profili versionati:** `general-v1` seleziona le verifiche native; `apple-portable-v1` aggiunge un sottoinsieme di raccomandazioni sotto forma di avvisi. Nessuno dei due profili certifica la compatibilità con un renderer Apple.

### Verifica

La [verifica registrata per la versione v0.1](https://github.com/Light2288/usdz-validator/blob/main/docs/verification/release-summary.md) comprende suite di test debug, release e Address Sanitizer, verifiche dedicate dei processi CLI, validazione degli schemi, esempi eseguibili, confronti con report attesi, verifiche su input avversi e misurazioni delle risorse. Questi risultati documentano la verifica del validatore sul sistema e sul corpus registrati.

Fixture originali e report attesi prefissati verificano contenitori malformati, gestione dei percorsi, lacune di copertura e contratti di output. Verifiche separate su asset reali documentano esiti sia positivi sia negativi del verificatore opzionale installato, mantenendo esplicite le lacune native sui riferimenti binari. Le misurazioni delle risorse costituiscono evidenza per i casi misurati, senza garantire universalmente memoria o tempi di esecuzione; la verifica dell'ambiente minimo e quella tra sistemi diversi restano rinviate.

### Limiti attuali

L'ispezione nativa dei riferimenti è lessicale e limitata al pacchetto. Non interpreta le dipendenze binarie USDC e non esegue una validazione completa della composizione o della conformità USD. Un esito positivo del verificatore opzionale non completa la copertura nativa dei riferimenti USDC. Il codice di uscita `0` indica che la politica configurata ha accettato il risultato; `--allow-incomplete` accetta le lacune della copertura nativa senza modificarla.

L'opzione `--usdchecker` è destinata a input attendibili e supporta la versione installata prefissata di Apple USD Tools 0.25.11. I suoi parser e resolver possono accedere a risorse del filesystem o della rete oltre il confine del pacchetto nativo; l'esecuzione esterna non dispone di una sandbox per filesystem e rete.

L'ambiente verificato registrato è macOS 27.0.1, Xcode 27.1 e Swift 6.4 su arm64. Il pacchetto dichiara strumenti Swift 6 e un deployment target macOS 15, ma la compatibilità con macOS 15 / Xcode 16 / Swift 6.0 resta prevista e non verificata. L'esecuzione su Intel e su sistemi diversi da macOS non rientra nel supporto della versione v0.1.

Il kit non ripara, converte, renderizza o mostra anteprime degli asset. L'accettazione di un risultato non certifica la piena conformità USD, la compatibilità con i renderer Apple o la sicurezza degli asset.
